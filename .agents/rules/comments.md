# 注释

## 1、注释只写代码没有写出的原因、前提和临时绕过

为什么：复述代码的注释会在改逻辑之后变成误导。

```ts
// ✅ 服务端把 0 和缺失都串成空字符串，这里只能按空字符串判缺失
const missing = rawScore === '';
// ❌ 按空字符串判断缺失
const missing = rawScore === '';
```

边界：改逻辑时，紧挨着的注释一起改，对不上就删。注释只覆盖紧跟着的那段。临时绕过写上 TODO 或 FIXME 和原因。

## 2、注释只写当前这段代码的现状和原因

为什么：原来怎样、需求号和设计稿链接会过期，读的人要理解的是这段代码现在为什么这样。

```ts
// ✅ 支付渠道 8 秒内不回包就按失败处理
const paid = await pay(orderId, { timeoutMs: PAY_TIMEOUT_MS });
// ❌ 原来是 3 秒，后来改成 8 秒，见需求 8841
const paid = await pay(orderId, { timeoutMs: PAY_TIMEOUT_MS });
```

边界：需求号、设计稿链接、MR 链接、版本沿革和别处实现不进注释。
